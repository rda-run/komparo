# Changelog

All notable changes to this project will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic
Versioning](https://semver.org/spec/v2.0.0.html).

## [1.0.0] - 2026-11-12

Snapshots written by earlier versions are still read. Regenerating them is
recommended, since older snapshots may have lost triggers and constraints
that share a name (see below).

### Changed

- **Stricter Column Comparison**: `validate` and `migrate` now compare column
  types with their length and precision, so `varchar(50)` against
  `varchar(255)` or `numeric(10,2)` against `numeric(12,4)` is reported as a
  mismatch. Validations that passed before may now fail.
- **Constraint and Trigger Keys**: Constraints and triggers are keyed by
  `table.name` in the snapshot instead of the name alone. Older snapshots are
  converted when loaded.
- **Stable Output**: `validate` reports and `migrate` scripts are generated in
  a deterministic order, so two runs over the same input produce the same
  result.
- **Dependencies**: Updated `lib/pq` to v1.12.3, `pflag` to v1.1.0, and the
  CI actions `checkout` and `setup-go` to v7. CI now takes the Go version
  from `go.mod`.

### Fixed

- **Read-Only Users**: `snapshot`, `validate` and `migrate` failed with a scan
  error for users that do not own the views in the schema. Triggers and
  sequences were also invisible to them, and function bodies came back empty.
  The schema is now read from `pg_catalog`, giving the same result for
  read-only users and owners.
- **Lost Triggers and Constraints**: Triggers or constraints with the same
  name on different tables (e.g., `set_updated_at`) overwrote each other in
  the snapshot, so all but one were lost.
- **Overloaded Functions**: Functions sharing a name got the return type, body
  and volatility of one another.
- **Views Extracted as Tables**: A view was treated as a table when another
  schema had a table with the same name.
- **Silent Function Errors**: A failure while extracting functions is now
  reported as a warning instead of being discarded.
- **Missing Transaction in Fix Script**: The script generated by `migrate`
  told the user to test with `ROLLBACK`, but never issued `BEGIN`, so every
  statement was committed as it ran. The script now opens a transaction.
- **Invalid Identifiers in Fix Script**: Identifiers are now quoted, fixing
  scripts for names such as `order`, mixed case columns, the `uuid-ossp`
  extension and the `"C"` collation. Enum values and extension versions are
  escaped.
- **`character varying` Length**: `migrate` created `varchar(n)` columns
  without their length.
- **Duplicate Index Statements**: `migrate` emitted both `ADD CONSTRAINT` and
  `CREATE INDEX` for primary keys and unique constraints, which made the
  script fail.
- **Foreign Key Ordering**: Foreign keys are now created after the keys they
  reference, and dropped before them.
- **Enum Values**: `migrate` ignored differences in enum values. It now
  generates `ALTER TYPE ... ADD VALUE` for missing values and a warning for
  values that cannot be removed.
- **Extension Version**: A version mismatch generated a `CREATE EXTENSION IF
  NOT EXISTS` that did nothing. `migrate` now generates `ALTER EXTENSION ...
  UPDATE TO`.
- **Fix Script Details**: Views no longer end with a double semicolon, and
  the generation time in the header is written in UTC.
- **Empty JSON Output**: `validate --format json` printed `null` instead of
  `[]` when there were no differences.
- **`.env` Values**: Passwords with spaces, quotes or backslashes in `.env`
  no longer break the connection string.
- **Remote Snapshot Timeout**: Fetching a snapshot over HTTP/HTTPS now times
  out after 30 seconds instead of waiting forever.

### Security

- **Password Redaction**: Passwords were not hidden for `postgresql://` URLs,
  quoted `password='...'` values or `?password=` query parameters, so they
  were printed by `snapshot` and written to the header of the SQL file
  generated by `migrate`.

## [0.4.1] - 2026-05-11

### Fixed

- **Migrate URL Support**: The `migrate` command now supports fetching JSON
  snapshots via HTTP/HTTPS URLs using the `-f` flag, matching the behavior
  of the `validate` command.

## [0.4.0] - 2026-05-09

### Added

- **Migration Script Generation**: New `migrate` command that generates SQL DDL
  fix scripts (`komparo_fix_*.sql`) to align a database with an expected schema
  snapshot. This command works with read-only database users and never executes
  DDL directly - the user must review and execute the generated SQL manually.
  - Analyzes differences between snapshot and live database
  - Generates ordered SQL statements respecting dependencies
  - Supports all schema object types: tables, columns, indexes, constraints,
    sequences, views, materialized views, triggers, functions, enums, extensions
  - DDL is organized in sections: DROP, ALTER, RECREATE, CREATE
  - Includes transaction wrapper with COMMIT/ROLLBACK for safe testing

### Security

- **Read-Only by Design**: The `migrate` command maintains Komparo's philosophy
  of never executing DDL directly. It only generates SQL files for manual review,
  allowing usage with restricted database users that have only SELECT privileges
  on system catalogs.

## [0.3.0] - 2026-03-24

### Added

- **Environment Variable Support**: Added support for loading database connection
  parameters (e.g., `PGSQL_HOST`, `PGSQL_USER`) from a `.env` file, making
  the `--db` flag optional for `snapshot` and `validate` commands.

### Security

- **Log Sanitization**: The `snapshot` command now obscures the password
  in the connection string output (e.g., `password=***`) to prevent
  accidental credential leaks in logs.

## [0.2.0] - 2026-03-24

### Added

- **Remote JSON Validation**: Added support for fetching JSON snapshot files
  via HTTP and HTTPS URLs in the `validate` command using the `-f` flag.

## [0.1.1] - 2026-03-23

### Added

- **Colored Terminals**: ANSI colored status indicators in the `validate`
  divergence table (Missing: Red, Mismatch: Yellow, Extra: Cyan) seamlessly
  integrated with Go's native `tabwriter`.

## [0.1.0] - 2026-03-23

### Added

- **Core CLI Foundation**: Basic Cobra CLI setup with `komparo` executable.
- **Snapshot Generation**: `snapshot` command to extract structural schema
  metadata from a PostgreSQL database into a standardized JSON file.
  - Supports extracting: Tables, Columns, Indices, Constraints, Sequences,
    Views, Materialized Views, Triggers, Functions, Enums, and Extensions.
- **Validation Engine**: `validate` command to compare a live database against a
  generated JSON snapshot.
- **Output Formats**: Tabular terminal output (default) and structured JSON
  output (`--format json`) for CI/CD integration.
- **GitHub Actions**: Automated CI pipeline running linting and tests on all PRs
  and pushes to `main`.
- **Makefile**: Pre-configured build scripts for Linux, Windows, and macOS
  (Intel & ARM64) with aggressive production optimizations (`CGO_ENABLED=0`,
  `-trimpath`, `-s -w`).
- **Version Command**: `version` subcommand printing the dynamically injected
  semver tag.
- **JSON Schema**: Formal specification for the expected
  `komparo-snapshot-v1.schema.json` output format.
